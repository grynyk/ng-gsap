Server-side rendering

injectGSAP runs in the write phase of Angular's render lifecycle, which never executes on the server. There is no isPlatformBrowser check to write and no afterNextRender wrapper to remember.

This site is the proof: it is built with outputMode: "static", so all eleven pages — every example on this site included — are rendered in Node with no DOM on every build. A checked-in script then asserts the server output contains real content and no GSAP side effects.

injectScrollTrigger and provideGsapRouteTransitions are server-safe the same way: both detect that there is no browser and stay inert instead of throwing.

Testing

ng-gsap/testing freezes GSAP so nothing moves except what you move, then lets you advance it by an exact number of milliseconds.

Because the global timeline is paused, gsap.set() does not apply inside a frozen test — it is a zero-duration tween, and a paused timeline never renders it. Set properties directly, or drive them through an animation you advance.

Note that fake timers cannot drive GSAP, in this or any wrapper: GSAP captures a direct reference to Date.now when its module first loads, so it keeps reading real wall-clock time no matter what vi.useFakeTimers() does to the global Date. advanceGsap seeks GSAP's global timeline instead, which sidesteps the clock entirely — that is why it is exact rather than approximately right.

Route transitions

ng-gsap/router animates routed views in and out app-wide, without touching a single component.

Angular's router does not wait for animations before destroying a view, so rather than blocking navigation, leave receives a pinned clone of the outgoing element and animates that. The clone keeps its classes and inline styles; what it cannot carry over is live state — canvas contents, video position, uncommitted form input. Animate only on enter for views where that matters.

Reduced motion

While the OS reports prefers-reduced-motion: reduce, animation collapses to its end state. Elements land where they belong instead of being stranded mid-from(), callbacks still fire, and ScrollTrigger still scrubs. It reacts to the setting changing mid-session and restores normal playback on teardown.
